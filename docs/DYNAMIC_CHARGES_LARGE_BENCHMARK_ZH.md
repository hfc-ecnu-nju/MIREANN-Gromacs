# 大体系正确性与性能实测

日期：2026-10-21。当前实现的大体系功能检查通过，但接口开销明显。以下均为本机实际运行结果，不是估算。

本文件记录**首次、优化前**的大体系测试。随后已优化源码并复测，当前结果见 [动态电荷接口性能优化与复测](DYNAMIC_CHARGES_OPTIMIZATION_ZH.md)；以下历史结果保留用于前后对照。

## 机器和控制条件

- Intel Core i7-10700，8 核 16 线程；每次 mdrun 使用单 rank、8 个 OpenMP 线程，绑核。
- NVIDIA GeForce GTX 1660 SUPER，6 GB；WSL Ubuntu 24.04，CUDA 12.1，cuFFT。
- 现有 Release、单精度、SIMD=None 构建。GPU PME 使用 cuFFT，CPU FFT 配置为 FFTPACK。不是经过平台最佳调优的正式发布构建，因此绝对速度不能泛化到其他机器或优化构建。
- 原生固定电荷参考使用同一修改版二进制，取消动态电荷环境变量；走未启用扩展的普通 GROMACS 路径，没有另行编译桌面原始源码。
- 所有测速均 GPU 短程 + GPU PME、CPU bonded、固定 nstlist=40，禁用 PME 自动调参；dt=2 fs，截断 1 nm、列表半径 1.2 nm，PME 网格间距 0.12 nm、4 阶插值。300 K v-rescale、无压强耦合。
- 普通 SPC 水盒：复制 GROMACS 自带 spc216.gro，分别为 13,824 和 46,656 个水分子，即 **41,472 和 139,968 个原子**。
- 更新区域为最前面的 100 个完整水分子，共 **300 原子**；通过全局编号映射更新，内部数据可随列表重建重排。
- 每个模式 3 次独立运行，每次 2,200 步；第 200 步清零计时，之后约 2,000 步采样。交替模式顺序，取 GROMACS 报告的 ns/day 中位数。
- 测速关闭电荷日志、逐帧轨迹和最终坐标输出；不读取逐步电荷文件。动态模式使用 identity 占位预测，仍执行完整区域读取、全体系 Frame 组装、验证、统计量刷新、短程打包和 PME 电荷上传。这些速度**不包含真实 ML 推理时间**。

## 速度结果

单位 ns/day，越大越快；括号为三次运行的最小值–最大值。

| 路径 | 41,472 原子 | 139,968 原子 |
|---|---:|---:|
| 固定电荷，GPU 积分 | **158.517**（158.355–158.884） | **51.676**（51.165–52.025） |
| 固定电荷，CPU 积分，默认 GPU buffer ops | **101.539**（101.256–102.179） | **34.200**（33.787–35.954） |
| 固定电荷，CPU 积分，关闭 GPU buffer ops | **99.003**（92.771–100.106） | **33.480**（33.370–33.567） |
| 当前动态电荷接口，CPU 积分 | **36.525**（36.477–36.545） | **16.722**（16.659–16.741） |

与同样采用 CPU 积分的固定电荷默认路径比较，动态接口吞吐量分别降低 **64.0%**、**51.1%**，相同模拟长度的运行时间约为 **2.78 倍**、**2.05 倍**。与原生 GPU 积分比较，运行时间约为 **4.34 倍**、**3.09 倍**。

这里的 ns/day 是短基准的吞吐量外推，没有实际模拟一天或完成 1 ns。每次完整基准只有 4.4 ps，不能据此证明长时间的热力学或数值稳定性。

## 正确性对照

独立固定拓扑把选区水的 O/H/H 电荷设为 -0.84/+0.42/+0.42 e；动态版从 -0.82/+0.41/+0.41 e 更新至相同目标。两者均保留相同选区三距离 LINCS 约束、体相 SETTLE 约束。这是因为 GROMACS 只允许一个 SETTLE 分子块，不能给两种不同电荷的水分别建两个 SETTLE 块。测速使用单一普通 SPC 拓扑，四种测速模式的拓扑完全相同，支持原生 GPU 积分。

固定拓扑对照关闭 GPU buffer ops，与动态版使用一致的短程打包/归约路径。40 步对照检查所有原子的坐标和力、势能，以及 0–40 步的全部 12,300 条选区电荷记录；包含 nstlist=40 的列表重建。两种规模均通过。

139,968 原子的二进制 TRR 对照：坐标最大最小镜像差 2.1935e-5 nm、RMS 差 6.8101e-7 nm；力相对 RMS 差 1.9440e-5；初始同坐标的最大力分量差 7.3242e-4 kJ/(mol·nm)。40 步后因混合精度和积分差异，力最大分量差 0.3856、RMS 差 0.01191 kJ/(mol·nm)。总势能最大差 2.875 kJ/mol，对约两百万 kJ/mol 的体系总势能，相对差 1.455e-6。

大盒子需要按周期性最小镜像比较位置。测试还增加了直接二进制 TRR 读取，避免 dump 文本仅六位有效数字对大坐标带来的精度损失。初期出现的测试拓扑限制、周期镜像及文本解析问题已在测试脚本中修正，没有因此修改引擎或用 maxwarn 放行。

## 每步连续改变电荷的独立参考

在 **139,968 原子**体系上继续运行 **200 步**，选区 300 原子每步按

`q_O(step) = -0.82 - 0.02 sin(2π step / 160)`，`q_H = -q_O/2`

改变电荷，每个水分子的电荷总和为零。检查全部 **60,300 条**电荷日志，全部与预测一致，覆盖第 40、80、120、160、200 步的邻居表重建。

抽取这条 GPU 轨迹的原始二进制坐标，在 0、40、80、120、160、200 步分别建立该时刻的固定电荷拓扑，取消动态扩展环境变量，用 **CPU 非键 + CPU PME rerun** 独立重算同一坐标的力。六帧全部通过：

| 步数 | O 电荷 e | 最大力分量差 kJ/(mol·nm) | 力相对 RMS 差 |
|---:|---:|---:|---:|
| 0 | -0.82 | 0.006592 | 1.177e-6 |
| 40 | -0.84 | 0.006104 | 1.200e-6 |
| 80 | -0.82 | 0.005981 | 1.200e-6 |
| 120 | -0.80 | 0.006714 | 1.197e-6 |
| 160 | -0.82 | 0.005981 | 1.199e-6 |
| 200 | -0.84 | 0.007080 | 1.195e-6 |

此处相对 RMS 差定义为力分量误差的 RMS 除以参考力分量的 RMS。独立参考没有经过动态更新分支。六帧参考支持大体系下电荷更新、原子重排后映射、短程力和 PME 力的一致性，没有发现旧电荷滞留到下一步的现象。它仍不覆盖全部可能拓扑。

连续变电荷检查包含大量电荷/力/坐标输出和逐步电荷文件读取，其 mdrun 日志速度不是上表的无输出测速条件，不能混用。

## 性能开销解释与后续优化方向

控制变量实测显示，单独关闭 GPU buffer ops 对固定电荷速度的影响约 2%–3%（存在短基准波动），无法解释动态接口的全部损失。当前只更新 300 个原子，但每一步仍会：

1. 重新打开并解析区域文件；
2. 重新分配/组装全体系全局到本地编号映射、坐标、电荷、类型；
3. 遍历整个体系重算 qsum/q2sum；
4. 完整刷新非键打包属性，并上传 GPU PME 的全体系电荷系数。

这些代码有每步 O(N) 的 CPU 工作和额外同步。代表性动态运行的 GROMACS 周期统计中，未单独计时的 `Rest` 占总时间约 **56%（4.1 万）**、**44%（14 万）**；扩展中的多数 CPU 组装工作位于这一未细分区域。但尚未给每个扩展函数单独插桩，不能把这些比例全部归因于某一个函数。

优先优化应缓存区域与只在原子重排时更新映射、复用缓冲区、按区域电荷变化增量维护统计量，再实现区域短程电荷 scatter 与更直接的设备 PME 系数更新。要恢复 GPU 积分，还需消除当前依赖 CPU 完整 xq 上传的设计，并为预测和力计算建立设备事件依赖；当前版本没有完成这些优化。

## 复现与原始数据

在工作区使用 WSL：

```bash
python3 tests/dynamiccharge_large_benchmark.py build-dynamiccharge-cuda/bin/gmx
python3 tests/dynamiccharge_large_varying.py build-dynamiccharge-cuda/bin/gmx
```

原始文件位于工作区 `tests/large-benchmark/`：

- `results.json`：两种规模的三次测速、范围、正确性对照结果；
- `{41472,139968}/bench-*.log`：每次 GPU 任务分配、周期统计与速度；
- `139968/varying/results.json`：六帧独立 CPU 参考的力误差；
- 各目录的 TOP/MDP/TPR、TRR、EDR、预测表和电荷日志可逐项复查。

本次没有修改引擎源码；新增测试脚本和报告，并更新补丁。桌面原始目录没有写回。结论限于当前单 rank、CPU 积分动态路径；大体系检查通过不意味着现有实现已经高效，也不构成真实 ML 势的能量一致性验证。
